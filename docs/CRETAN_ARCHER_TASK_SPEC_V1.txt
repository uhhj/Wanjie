==================================================
11. Idle
==================================================

轻装弓箭手待机。

要求：
- 比 Roman Guard 更轻一点
- 但不要夸张晃动
- bow 稳定持握
- quiver 和 cloak 有很小幅度滞后
- 头部基本稳定

==================================================
12. Walk
==================================================

这是复用验证的重要项。

要求：

- 比 Roman Guard 更轻快
- 步幅可略大一点
- 骨盆有轻微上下起伏
- 躯干有轻微反向补偿
- bow hand 保持持弓逻辑
- cloak 有很小延迟
- quiver 不应明显穿模
- 192/256px 战斗尺寸下自然

不要做奔跑。

==================================================
13. Attack_01（弓箭专用）
==================================================

这是本单位的核心验证项。

推荐阶段：

0.00
rest / ready

0.10
开始抬弓

0.22
另一只手取箭 / 接近弓弦位置
（如果不做取箭显式动作，也必须视觉上形成拉弓准备）

0.35
拉弓

0.48
满弓瞄准

0.52 左右
ATTACK_RELEASE_EVENT

0.56
箭离弦，bow_string恢复

0.70
收势

0.85~0.95
回到ready

要求：

- 动作方向一眼能看出是射箭
- bow hand 与 draw hand 关系清楚
- 不要把近战刺击模板硬改成“像拿弓戳人”
- bow_string 变化要成立
- arrow_single 在释放前存在，在释放后消失
- 释放事件恰好1次

==================================================
14. attack_release 事件
==================================================

Rig层需要提供：

signal attack_release

AnimationPlayer method track中恰好调用1次。

禁止：
- 用timer猜测
- 多次触发
- 把箭发射逻辑写死在动画脚本里

Rig层只负责发事件。

未来 Combat System 才负责：
- 生成投射物
- 伤害
- 速度
- 弹道
- 命中

==================================================
15. Hit
==================================================

短促受击。

要求：
- 小幅后仰
- 持弓不完全丢失
- 不要夸张

==================================================
16. Death
==================================================

轻装单位倒地。

可比 Roman Guard 略轻一些，
但仍保持写实感。

不做ragdoll。

==================================================
17. Combat-scale 动画验收
==================================================

对所有动画生成：

256px
192px

100%显示审查。

重点看：

- walk是否自然
- attack_01是否一眼看出拉弓放箭
- bow / bow_string / arrow关系是否正确
- quiver是否稳定
- cloak是否过度穿插
- limbs是否断裂
- 实际战斗尺寸是否可接受
